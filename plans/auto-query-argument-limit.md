# Plan — Auto-query argument explosion (umbrella)

> Umbrella doc for the whole feature. **Step 1 (the hard part — grouping
> propagated args into a synthesized input object) is specified separately in
> `hoisted-args-object-step1.md`.** This doc keeps the overall intent plus the
> *later* steps (skip cap, config key, CLI warnings, docs). Supersedes the old
> "prune over-collected queries" design — pruning is now only a safety cap.

## Goal
Auto-generated operations turn every projected field argument into a top-level
operation variable → a flat method parameter. For large schemas (GitHub `node`
≈ 1219 params) this produces unusable / non-compiling signatures, worst in Java
(positional). Fix: keep declared args as direct parameters; move propagated args
into a synthesized `<Op>FieldArgs` input object. A skip cap catches the absurd tail.

## Settled model (shared by all steps)
- **One uniform rule, every query.** Generation never branches on declared-query
  vs auto-generated-query. Per argument: **declared → direct parameter;
  propagated → field in the `<Op>FieldArgs` object.** The *only* place query type
  matters is the skip cap, which applies to auto-generated queries only.
- **Always group**, **all four languages**, **client-side only** (the GraphQL
  document keeps flat `$variables`; the synthetic arg is expanded back into them).
- **Detection via `isDeclared` flag** on `GLArgumentDefinition` (default `true`),
  set `false` for propagated args at the single choke point `_addGeneratedArgument`.

## Step 1 — grouping (see `hoisted-args-object-step1.md`)
The mechanics live there. One-paragraph summary so this doc stays consistent: a
dedicated `gl_grammar_hoist_args_extension.dart` pass swaps each operation's
propagated args out of `def.arguments` and inserts ONE synthetic arg whose type
is a synthesized `<Op>FieldArgs` input (registered in `inputs`, collision-suffixed,
carrying `hoistArgsInput` so serializers can expand it). Method signatures fall
out for free; the shared query-string serializer and each language's variables
map expand the synthetic arg back into flat `$variables`.

## Step 2 — skip cap (safety net)
Grouping handles normal explosions, but beyond an absurd cap (even a 1219-field
object isn't worth emitting) skip the auto-generated query and warn.

- **Metric:** the propagated-arg count = the operation's `hoistArgsInput` input's
  field count (`arg.hoistArgsInput?.fields.length ?? 0`). 0 for ops with no
  propagated args.
- **`GLQueryDefinition.isAutoGenerated`** (bool, default `false`) — set `true` only
  at the auto-gen construction site in `gl_grammar_fragment_extension.dart`
  (`_generateForField`); hand-written path stays `false`. Gates the cap so
  hand-written queries are never pruned.
- **Prune pass** in `gl_parser.dart`, run right after the hoist pass / before
  `createProjectedTypes()`: for each auto-generated query whose propagated count
  > cap, remove the query AND its synthesized `<Op>FieldArgs` input (no orphan
  type), and record a `SkippedAutoQuery(name, type, count, cap)` on a public
  `skippedAutoQueries` list for the CLI.
- `cap == null` disables skipping entirely (always group, never skip).

## Step 3 — config key
- `ClientLanguageConfig` base: `int? get autoGenerateQueriesArgumentLimit => 200;`
  (high default — grouping handles normal cases; the cap only catches the absurd).
- Each of the 4 language configs: `@override final int? autoGenerateQueriesArgumentLimit;`,
  constructor param (default 200), `fromJson`:
  `json['autoGenerateQueriesArgumentLimit'] as int? ?? 200`. `null` ⇒ cap off.
- `grammar_factory.dart` `createGrammar` client branch: thread
  `autoQueryArgumentLimit: lang.autoGenerateQueriesArgumentLimit` into `GLParser`.

## Step 4 — CLI warnings (main.dart)
After parse / before generation, one `⚠` line per `skippedAutoQueries` entry:
the op name/type, its propagated count, the cap, and the escape hatch ("write a
custom query with a narrower selection, or raise autoGenerateQueriesArgumentLimit").
Parser stays side-effect-free (collects, never prints).

## Step 5 — docs (follow-up)
`site/docs-src/*` autoGenerateQueries page: document the `<Op>FieldArgs` object,
the param name (`fieldArgs`), and the `autoGenerateQueriesArgumentLimit` cap +
warning. Sync `site/llms.txt` / `llms-full.txt` per `site/CLAUDE.md`.

## Edge cases / correctness notes
- **Same code shape for every query.** Generation never branches on
  declared-query vs auto-generated-query; the per-arg rule is applied identically.
  A hand-written query that declares its `$variables` simply has no propagated
  args, so it keeps direct params — that's the rule, not a special case.
  `isAutoGenerated` exists solely to gate the cap.
- **Skip cap only touches auto-generated queries** (`isAutoGenerated`), never
  hand-written — even a deliberately huge custom query is the developer's choice.
- **Pruned query's input removed** in the same pass so no orphan `<Op>FieldArgs`
  type is emitted.

## Out of scope
- `@glForceAutoQuery` / `forceAutoGenerateQueries` to bypass the cap.
- Hierarchical (selection-tree) object shape — flat only for now.
- Narrowing the all-fields projection itself (depth/scope) — separate lever.
