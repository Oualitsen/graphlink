# GraphLink Site

## What this is

Documentation website for **GraphLink** (`graphlink.dev`). Built with MkDocs Material and served via nginx inside a Docker container.

## Structure

```
site/
  docs-src/               # Source files — edit these
    index.md              # Docs overview / landing page
    philosophy.md
    getting-started.md
    dart-client.md
    java-client.md
    typescript-client.md
    spring-server.md
    caching.md
    directives.md
    skip-directives.md
    configuration.md
    ai-agents.md
    _llms_header.txt      # Header prepended to llms-full.txt (full LLM context)
    _llms_concise_header.txt  # Header prepended to llms.txt (concise LLM context)
  hooks/
    generate_llms.py      # MkDocs hook — generates llms.txt, llms-full.txt, sitemap.xml into dist/
  overrides/              # MkDocs theme overrides
  dist/                   # Build output — DO NOT edit (regenerated by mkdocs build)
  mkdocs.yml
  Dockerfile
  nginx.conf
  favicon.svg             # Copied into dist/ by Dockerfile
  robots.txt              # Copied into dist/ by Dockerfile
```

## Blog

Articles live in `docs-src/blog/posts/<slug>.md` (MkDocs Material blog plugin; URL `https://graphlink.dev/blog/<slug>.html`).

```bash
make new-post slug=graphql-caching-flutter title="GraphQL caching in Flutter" topic=Dart id=D-02
```

- Scaffolds a **draft** from `templates/post.md`. `draft: true` (or a future `date`) keeps it out of `make build`, `sitemap.xml`, `llms.txt` and `llms-full.txt`; remove the line to publish. `make serve-docs` still shows drafts.
- Front matter: `date`, `slug` (set it explicitly — it is the URL), `categories` (one topic), `description` (≤155 chars), optional `author`, plus bookkeeping fields (`id`, `demo_repo_path`, `docs_page`).
- Video: uncomment the `video-embed` block in the template and put the YouTube ID in it.
- Published posts also get `llms/blog/<file>.txt`, a `BlogPosting` JSON-LD block, OG tags and a sitemap entry (all from `hooks/generate_llms.py` + `overrides/main.html`).
- The site is static: a post with a future date goes live only on the next deploy after that date, not automatically.

## Build & deploy

```bash
make build    # runs mkdocs build → outputs to dist/
make serve    # build + serve dist/ locally on :8080
make release  # build → Docker image → push → kubectl rolling restart
```

**Only `dist/` is served in production** (Dockerfile copies `dist/` → `/usr/share/nginx/html/`).  
**Never edit `dist/` directly** — it is fully regenerated by `mkdocs build`.

## How llms.txt and llms-full.txt are generated

The hook `hooks/generate_llms.py` runs automatically during `mkdocs build` and writes:
- `dist/llms.txt` — concise overview from `_llms_concise_header.txt` + frontmatter links from each page
- `dist/llms-full.txt` — full context from `_llms_header.txt` + complete markdown of every page
- `dist/llms/<page>.txt` — raw markdown of each page (the links in `llms.txt` point here)
- `dist/sitemap.xml`

**To update LLM context:** edit `docs-src/_llms_header.txt` and/or `docs-src/_llms_concise_header.txt`, then run `make build`.

## When you update a doc page

1. Edit the relevant `docs-src/*.md` file.
2. If the page's summary or key features changed significantly, update its frontmatter `description:` — this feeds into `llms.txt` page links automatically.
3. If a new directive, config option, or feature was added, update `_llms_header.txt` and `_llms_concise_header.txt` accordingly.
4. Run `make build` to regenerate `dist/`.

## Analytics

GoatCounter (cookieless, no consent banner), site code `graphlink`, dashboard at `https://graphlink.goatcounter.com`. The script tag is in `overrides/main.html` (`extrahead`). It records referrers and `utm_*` query params; localhost is ignored by default.

## Versioning

The current version is referenced in:
- `docs-src/_llms_header.txt` — `## Supported targets (as of vX.Y.Z)`
- `docs-src/_llms_concise_header.txt` — same line

Update both when cutting a new release, then rebuild.
