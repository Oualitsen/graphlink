# GraphLink

> GraphQL code generation tool for Dart, Flutter, Java, TypeScript, Kotlin, and Spring Boot. Open source. MIT License.

GraphLink is a command-line tool (`glink`) that reads a GraphQL schema and generates fully type-safe
client and server code. Developers define their API once in a `.graphql` schema file and run
`glink` to get production-ready, idiomatic code for their target language.

## What GraphLink generates

- **Dart / Flutter client**: typed data classes, input classes, enums, toJson/fromJson, a fully
  typed GraphQL client with named-parameter constructors, and generated HTTP/WebSocket adapters
  (Dio or package:http, with auto-reconnect WebSocket) — zero boilerplate to set up.
- **Java client**: typed POJOs with builder pattern, a GraphQL client where every call returns a
  concrete typed response — no generics, no TypeReference, no casting at the call site. Ships with
  generated adapters (Java 11 HttpClient + WebSocket, or OkHttp) and a Jackson/Gson codec so a
  one-liner `new GraphLinkClient(url)` is all you need.
- **TypeScript client**: typed interfaces, enums, input types, a fully typed client with Fetch
  (default) or Axios HTTP adapter, optional RxJS observables (Angular-friendly), and a default
  WebSocket adapter for subscriptions with auto-reconnect. Works in Angular, React, Vue, Svelte, and Node/Bun.
- **Kotlin client**: typed `data class` types and inputs, enums with `toJson`/`fromJson`, and a
  coroutine-based GraphQL client using `kotlinx.serialization`. Single-method `GraphLinkClientAdapter`
  interface (a Kotlin `fun interface`) is all you need for HTTP. Subscriptions via OkHttp WebSocket
  with auto-reconnect (or `"none"` to bring your own). Works in Android, JVM server projects, and KMP.
- **Spring Boot server (Java or Kotlin)**: controllers, service interfaces, repository stubs, and
  input classes generated from the schema's type definitions and queries. Supports MVC and reactive
  (WebFlux) mode. Java target: injectable HttpClient/OkHttpClient adapters, plus a reactive client
  mode (`asyncStyle`: Reactor/RxJava3/Mutiny). Kotlin server target: data-class types, coroutine
  services, optional `Dispatchers.IO` offloading for blocking service layers.

## Key differentiators

- **No generics at the Java call site.** Other Java GraphQL clients require
  `TypeReference<GraphQLResponse<GetUserData>>` on every call. GraphLink generates fully-resolved
  return types: `client.queries.getUser(id).getUser()` is all you write.
- **Built-in caching via schema directives.** Cache behavior is declared in the schema itself
  using `@glCache(ttl, tags)` and `@glCacheInvalidate(tags)`. Supports tag-based invalidation,
  partial query caching (per-field TTL), and offline fallback (`staleIfOffline`).
- **Zero runtime dependency.** Generated code has no dependency on GraphLink at runtime. Stop
  using it any time — the generated files keep compiling and working.
- **Only what the server needs.** Unlike ferry (which sends the entire schema), GraphLink generates
  precise queries containing only the requested fields. This is required for Spring Boot's strict
  schema validation to pass.
- **Watch mode.** Run `glink -w` to watch schema files and regenerate automatically on every save.
- **Single source of truth.** The schema drives both ends. No duplicate type definitions. No
  schema drift. Adding a field means editing one file.
- **Two-layer server-side access control.** `@glSkipOnClient` enforces field access on the server
  at two levels. Level 1 (always active): a `@SchemaMapping` is generated that throws
  `GraphQLException("Access denied")` — no runtime access regardless of the client. Level 2
  (`generateSchema: true`): the field is stripped from the schema Spring Boot serves — invisible
  in GraphiQL and rejected at validation before execution. Neither level depends on the generated
  client — any raw GraphQL client or introspection tool is blocked.
- **ID/object field-pair pattern.** `@glSkipOnServer` and `@glSkipOnClient` are designed to be
  used on different fields of the same type. The raw foreign key (`cashierId @glSkipOnClient`)
  stays on the server for persistence; the resolved object (`cashier @glSkipOnServer(batch: true)`)
  is loaded by the server and delivered to the client. This eliminates N+1 queries and keeps
  each side's model clean without any shared representation.
- **WebSocket auto-reconnect by default.** Every generated WebSocket adapter — Dart, Java, TypeScript,
  and Kotlin — reconnects automatically after a network drop, server restart, or idle timeout.
  This is where most GraphQL client libraries fall short: they generate the subscription method but
  leave reconnection to the user. GraphLink handles the full connection lifecycle out of the box,
  integration-tested across all targets.
- **Inline error handling (`@glCaptureErrors`).** Annotate any query or mutation with
  `@glCaptureErrors` (or set `captureErrors: true` in config) to return a `FullResponse` with
  `data` and `errors` side by side instead of throwing on GraphQL errors. Dart, Java, TypeScript, and Kotlin.
- **Selective auto-generation (`autoGenerateQueriesFor`).** On large schemas, `autoGenerateQueries: true`
  generates a client method for every root field — which can be hundreds of methods. `autoGenerateQueriesFor`
  lets you list exactly which queries, mutations, and subscriptions to auto-generate. Unknown names cause a
  build error. Supported in all four client targets (Dart, Java, TypeScript, Kotlin).
- **Propagated-arg grouping and limit.** When auto-generating queries, nested field arguments collected
  from sub-fields are automatically grouped into a synthesized `<Op>FieldArgs` input object (the single
  `fieldArgs` parameter), so method signatures never explode into hundreds of positional parameters.
  A configurable `autoGenerateQueriesArgumentLimit` (default 200) skips any auto-generated operation
  whose `fieldArgs` would exceed the cap and prints a `⚠` warning with instructions. Hand-written
  operations are never affected.
- **Oversized fragment cap (`maxFragmentBodySize`).** When `generateAllFieldsFragments: true` is used
  on a very large schema (e.g. Shopify's public API), individual `_all_fields` fragment bodies can reach
  60 KB+, bloating the compiled binary (JVM constant pool, Dart exe) and every network request that
  references them. `maxFragmentBodySize` (default 8192 chars) silently omits any `_all_fields` fragment
  whose serialized body exceeds the cap, along with any auto-generated operations that depend on it.
  Set to `null` to disable the cap and always generate all fragments. Applies to all four client
  targets (Dart, Java, TypeScript, Kotlin).
- **Barrel file generation.** Dart and TypeScript generators emit a single barrel/index file that
  re-exports all generated enums, inputs, types, and interfaces. One import covers the entire layer.
- **Flutter UI widget generation.** The `flutter` config block generates display widgets for output
  types and form widgets for input types, with extensive layout and style options.
- **Keyword-safe identifiers.** A GraphQL field, input field, argument, or enum value may legally be
  named after a reserved word in the target language (`default`, `class`, `object`, `val`, ...).
  GraphLink keeps two names per identifier: the wire name (the original GraphQL token, used in the
  query string, JSON keys, and variables map — never altered) and the code name (a sanitized
  identifier used only where the language needs one). On collision an underscore is appended
  (`default` -> `default_`), with numeric resolution for further clashes (`default_2`). A leading
  underscore is sanitized too, by moving it to the end (`_link` -> `link_`, and enum values
  `_ACTIVE` -> `ACTIVE_`): in Dart a leading underscore means private, so this rule is applied across
  all languages for consistency. The
  serialization layer bridges the two so the wire format is unchanged. Enum values get the same
  treatment: because Java/Kotlin couple a constant to its wire string via `valueOf()`/`name()`,
  GraphLink emits an explicit `switch`/`when` mapping — but only when sanitization occurred, so
  non-colliding enums keep their clean form. On Spring Boot, a sanitized resolver argument is pinned
  to the wire name with `@Argument(name = "default")`. TypeScript needs no sanitization (reserved
  words are legal as object properties and enum members). The whole mechanism is automatic with no
  configuration.

- **Strict server generation with projections (v5.0.0+, breaking change).** Server-generated types
  and interfaces (Java Spring and Kotlin Spring) now enforce the schema's real nullability by
  default — a non-null field stays non-null on getters/constructors/setters, instead of the
  previous always-nullable model. Every type/interface also gets a generated `GL<Type>Projection`
  companion interface (all fields nullable) to represent partially-fetched data. `@glServerLenient`
  opts a type back into the old all-nullable behavior; `@glReturnsProjection` opts a resolver field
  into returning `GL<Type>Projection` (with `DataFetchingEnvironment` auto-injected). Migration:
  annotate legacy types/resolvers before upgrading if they relied on always-nullable fields.
- **Unconditional identifier normalization (v5.0.0+, breaking change).** Every generated
  identifier — field names, argument names, enum values, type/input/interface/union/enum names —
  is unconditionally rewritten to the target language's canonical casing (lowerCamelCase fields,
  SCREAMING_SNAKE Java/Kotlin enum values, PascalCase TypeScript enum values, PascalCase type
  names). Not opt-in. Because generated identifiers can now diverge from wire names,
  `toJson`/`fromJson` generation became mandatory on every serializer (previously suppressible via
  a `generateJsonMethods` flag, now removed).
- **Controllers return `Map`/`List<Map>` (v5.0.0+, breaking change).** Java Spring, Kotlin Spring,
  and Express/Apollo controllers now serialize responses via the type's `toJson()` at the
  controller boundary and return `Map<String, Object>` / `List<Map<String, Object>>` instead of
  typed objects — service interfaces are unaffected. Java Spring controllers also bind mutation
  input arguments as `Map<String, Object>`, converting via the input's `fromJson()`.
- **Kotlin enum `fromJson` now throws on unknown values (v5.0.0+, breaking change).** Signature
  changed from `fun fromJson(value: String?): T?` to `fun fromJson(value: String): T` — an
  unrecognized wire value throws `IllegalArgumentException` instead of returning `null`.

## Supported targets (as of v5.0.0)

- Dart client (stable)
- Flutter client (stable)
- Java client (stable — blocking by default; optional reactive mode via `asyncStyle`: Reactor, RxJava3, Mutiny)
- Spring Boot server (stable, MVC and reactive/WebFlux — Java and Kotlin targets, strict-by-default nullability)
- TypeScript client (stable — fetch/axios, RxJS observables, WebSocket subscriptions)
- Kotlin client (stable — coroutines, kotlinx.serialization, OkHttp WebSocket)
- Express / Node.js server (planned)
- Go (planned, demand-based)

## Installation

Download the prebuilt binary from GitHub Releases:
https://github.com/Oualitsen/graphlink/releases/latest

Platforms: Linux (x86_64), macOS (ARM64), Windows (x86_64)

## Basic usage

```bash
glink                   # auto-discover glink.json / glink.yaml / glink.yml
glink -c glink.json     # explicit config path (JSON, YAML, or YML)
glink -w                # watch mode — regenerate on schema change
glink -v                # print version
glink -h                # show help
```

## Configuration (glink.json / glink.yaml)

```json
{
  "schemaPaths": ["schema/*.gql"],
  "mode": "client",
  "typeMappings": { "ID": "String", "Float": "Double", "Int": "Integer", "Boolean": "Boolean" },
  "unknownScalarType": "Object",
  "outputDir": "src/main/java/com/example/generated",
  "clientConfig": {
    "java": {
      "packageName": "com.example.generated"
    }
  }
}
```

## Caching directives

```graphql
type Query {
  getCar(id: ID!): Car! @glCache(ttl: "5m", tags: ["cars"])
}
type Mutation {
  createCar(input: CreateCarInput!): Car! @glCacheInvalidate(tags: ["cars"])
}
```
