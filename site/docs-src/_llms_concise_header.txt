# GraphLink

> GraphQL and REST code generation tool for Dart, Flutter, Java, TypeScript, Kotlin, Swift, Python, Go, Spring Boot and Express/Apollo. Open source. MIT License.

GraphLink is a command-line tool (`glink`) that reads a GraphQL schema and generates fully type-safe
client and server code. Developers define their API once in a `.graphql` schema file and run
`glink` to get production-ready, idiomatic code for their target language.

## What GraphLink generates

- **Dart / Flutter client**: typed data classes, input classes, enums, toJson/fromJson, a fully
  typed GraphQL client with named-parameter constructors, and generated HTTP/WebSocket adapters
  (Dio or package:http, with auto-reconnect WebSocket) — zero boilerplate to set up.
- **Java client**: typed POJOs with builder pattern, a GraphQL client where every call returns a
  concrete typed response — no generics, no TypeReference, no casting at the call site. Ships with
  generated adapters (Java 11 HttpClient + WebSocket, or OkHttp) and a Jackson/Gson codec so a
  one-liner `new GraphLinkClient(url)` is all you need.
- **TypeScript client**: typed interfaces, enums, input types, a fully typed client with Fetch
  (default) or Axios HTTP adapter, optional RxJS observables mode (Angular-friendly), and a default
  WebSocket adapter for subscriptions. Works in Angular, React, Vue, Svelte, and Node/Bun.
- **Kotlin client**: typed data classes, input classes, enums, and a coroutine-based GraphQL client
  using `kotlinx.serialization`. Supports queries, mutations, and subscriptions (OkHttp WebSocket
  with auto-reconnect). Works in Android, JVM server projects, and Kotlin Multiplatform.
- **Swift client**: typed `Sendable` structs, enums, and an async/await GraphQL client with no
  third-party dependency — `URLSession`/`URLSessionWebSocketTask` (Foundation) for HTTP,
  subscriptions (with auto-reconnect), and multipart uploads. Works on Apple platforms and Linux.
- **Python client**: pydantic v2 models (snake_case fields, `to_json`/`from_json`), an `asyncio` client with an
  injectable adapter, default `httpx` and `websockets` adapters (subscriptions auto-reconnect), file uploads,
  caching and persisted queries. Requires pydantic >= 2.10.
- **Go client**: plain structs with `json` tags in one package, a `context`-aware client whose methods return
  `(value, error)`, channel subscriptions, default `net/http` and `coder/websocket` adapters, file uploads, caching and
  persisted queries. Requires Go 1.22+.
- **Spring Boot server (Java or Kotlin)**: controllers, service interfaces, repository stubs, and
  input classes generated from the schema's type definitions and queries. Supports MVC and reactive
  (WebFlux) mode. Strict-by-default nullability; controllers serialize responses to a `Map` via
  `toJson()`, and `@glServerLenient` opts a type into all-nullable fields for partial population.
- **Express / Apollo server (TypeScript)**: typed service interfaces, generated Apollo Server
  resolvers, `graphql-ws` subscriptions, and an optional ready-to-run `createServer(services)` entry
  point. DataLoader-backed batch mappings; same strict/`toJson()`-boundary model as Spring targets.

## Key differentiators

- **Classes and client operations, generated together.** Other generators stop at types and leave the client to
  you. GraphLink also generates the typed client methods, serialization, caching and transport wiring.
- **A generated backend you only fill in.** Spring Boot (Java, Kotlin) and Express/Apollo controllers/resolvers
  call service interfaces you implement. Handlers are asynchronous by default (`CompletableFuture` on Java MVC,
  `Mono` on reactive, `suspend` on Kotlin, `async` on Express), so sibling query fields can run concurrently.
- **N+1 is built in.** `@glSkipOnServer(batch: true)` generates a `@BatchMapping` or a per-request DataLoader.
- **No generics at the Java call site.** Other Java GraphQL clients require
  `TypeReference<GraphQLResponse<GetUserData>>` on every call. GraphLink generates fully-resolved
  return types: `client.queries.getUser(id).getUser()` is all you write.
- **Custom queries and mutations — fully typed.** Write standard GraphQL operation documents
  alongside your schema. GraphLink generates a typed client method, a typed response class, and
  projected types for every hand-written query, mutation, and subscription. Combine multiple
  resolvers in one operation and get one unified typed response.
- **Built-in caching via schema directives.** Cache behavior is declared in the schema itself
  using `@glCache(ttl, tags)` and `@glCacheInvalidate(tags)`. Supports tag-based invalidation,
  partial query caching (per-field TTL), and offline fallback (`staleIfOffline`).
- **Persisted queries (APQ).** Set `persistedQueries: "apq"` on any client and long operations are sent as a
  SHA-256 hash, retried once with the text on `PersistedQueryNotFound` (Apollo-compatible). Optional
  `persistedQueriesUseGet` sends hash-only queries over GET; mutations always use POST.
- **Zero runtime dependency.** Generated code has no dependency on GraphLink at runtime. Stop
  using it any time — the generated files keep compiling and working.
- **Only what the server needs.** Unlike ferry (which sends the entire schema), GraphLink generates
  precise queries containing only the requested fields. This is required for Spring Boot's strict
  schema validation to pass.
- **Watch mode.** Run `glink -w` to watch schema files and regenerate automatically on every save.
- **Single source of truth.** The schema drives both ends. No duplicate type definitions. No
  schema drift. Adding a field means editing one file.
- **WebSocket auto-reconnect by default.** Every generated WebSocket adapter reconnects automatically
  after a network drop, server restart, or idle timeout — in all seven clients.
  Most GraphQL clients generate the subscription method but leave reconnection to the user.
  GraphLink handles the full connection lifecycle, integration-tested across all targets.
- **Generic pre-resolver interceptor (`@glIntercept`).** Annotate a root field, a `@glSkipOnServer`
  mapping field, or a whole `type` block with `@glIntercept(tag: "...")` to run a single generated
  `runBefore(tag, operation, args, context)` hook before the resolver — throw to deny, return to
  proceed. One implementation covers every annotated field. Java Spring, Kotlin Spring, and
  Express/Apollo.
- **Inline error handling (`@glCaptureErrors`).** Annotate any query or mutation with
  `@glCaptureErrors` (or set `captureErrors: true` in config) to return a `FullResponse` with
  `data` and `errors` side by side instead of throwing. Every client target.
- **Selective auto-generation (`autoGenerateQueriesFor`).** On large schemas, `autoGenerateQueries: true`
  generates a client method for every root field. `autoGenerateQueriesFor` lets you list exactly which
  queries, mutations, and subscriptions to auto-generate. Unknown names cause a build error at generation
  time. Supported in every client target.
- **Propagated-arg grouping and limit.** Nested field arguments collected during auto-generation are
  grouped into a single `fieldArgs` object parameter so method signatures stay manageable.
  `autoGenerateQueriesArgumentLimit` (default 200) skips any auto-generated operation whose `fieldArgs`
  would exceed the cap and prints a `⚠` warning. Hand-written operations are never skipped.
- **Oversized fragment cap (`maxFragmentBodySize`).** When `generateAllFieldsFragments: true` is used on
  a very large schema (e.g. Shopify), individual `_all_fields` fragment bodies can reach 60 KB+, bloating
  the compiled binary and every network request. `maxFragmentBodySize` (default 8192 chars) silently
  skips any fragment whose serialized body exceeds the cap, along with any auto-generated queries that
  depend on it. Set to `null` to disable. Applies to every client target.
- **Barrel file generation.** Dart and TypeScript generators emit a barrel/index file that
  re-exports all generated types, inputs, and enums from a single import.
- **Keyword-safe identifiers.** A GraphQL field, input field, argument, or enum value named after a
  target-language reserved word (`default`, `class`, `object`, `val`, ...) is automatically sanitized
  (`default` -> `default_`) while the original name is preserved on the wire (JSON keys, query string,
  variables). A leading underscore is also sanitized by moving it to the end (`_link` -> `link_`, and
  enum values `_ACTIVE` -> `ACTIVE_`), because in Dart a leading underscore means private — applied across all languages for consistency.
  Enum constants and Spring `@Argument` bindings are pinned back to the wire name. Automatic,
  no configuration. TypeScript needs no sanitization for reserved words (legal as properties).

- **Unconditional identifier normalization (v5.0.0+, breaking).** All generated identifiers are
  unconditionally rewritten to canonical target-language casing (not opt-in). `toJson`/`fromJson`
  generation is now mandatory on every serializer since generated names can diverge from wire names.
- **Controllers return `Map`/`List<Map>` (v5.0.0+, breaking).** Java Spring, Kotlin Spring, and
  Express/Apollo controllers serialize via `toJson()` at the boundary; service interfaces unchanged.
  Java Spring controllers bind mutation inputs as `Map<String, Object>` via generated `fromJson()`.
- **Reactive Java client (`asyncStyle`).** `clientConfig.java.asyncStyle` generates a client
  returning `Mono`/`Single`/`Uni` (Reactor/RxJava3/Mutiny) instead of blocking calls.

- **REST operations (`@glRest*`, v6.0.0+, all seven clients).** Fields of `Query`/`Mutation` annotated with
  `@glRest(path, method, ...)` are served over HTTP/JSON instead of GraphQL, from the same schema and generated
  client. Arguments get explicit roles (`@glRestPath`, `@glRestParam`, `@glRestHeader`, `@glRestBody`,
  `@glRestField`, `@glRestPart`). `@glRestNullable` (on an operation, on the `Query`/`Mutation` type, or for the
  whole project with the top-level `restNullable` option) decodes into a copy of the response type with every
  field nullable (`Product` gives `ProductRest`).
- **Scalar codecs (v6.0.0+).** A `typeMappings` entry can be an object, `{"type", "import", "fromJson", "toJson",
  "jsonType"}`, to convert a custom scalar when it is decoded and encoded, in every client.
- **Hardened decoding (v6.0.0+, breaking).** Empty or non-GraphQL responses fail with the client's error type; Swift
  decoders `throw`; Python and Go decode explicitly; TypeScript checks scalars at run time; Java and Kotlin decode
  `Int` and `Long` exactly. Uploads stream in every client.
- **Why REST (v6.0.0+).** Try GraphLink on an existing REST API with no GraphQL server, get a client-side cache
  (`@glCache` tags) shared by REST and GraphQL, and migrate to GraphQL one field at a time by removing `@glRest`.
  https://graphlink.dev/why-rest.html
- **Directives are validated (v6.0.0+, breaking).** Every directive must be built in or declared with
  `directive @name ... on ...`; unknown or misspelled arguments, wrong value kinds and wrong locations fail
  generation. `glink --print-directives` prints the declarations of GraphLink's own directives for your IDE.

## How GraphLink compares

One schema generates clients for seven languages and Spring Boot and Express/Apollo servers, with no runtime
library. Apollo Kotlin, Apollo iOS, genqlient (Go), ariadne-codegen (Python), GraphQL Code Generator (TypeScript),
Netflix DGS (Java) and ferry (Dart) each cover one language or framework. Another tool fits better if you need a
normalized client cache or optimistic updates (Apollo, ferry), or your language is not one of the seven.
Details: https://graphlink.dev/philosophy.html#how-it-compares

## Supported targets (as of v6.0.0)

- Dart client (stable)
- Flutter client (stable, including UI widget generation)
- Java client (stable — optional reactive mode via `asyncStyle`)
- Spring Boot server (stable, MVC and reactive/WebFlux — Java and Kotlin targets)
- TypeScript client (stable — fetch/axios, RxJS observables, WebSocket subscriptions)
- Kotlin client (stable — coroutines, kotlinx.serialization, OkHttp WebSocket)
- Swift client (stable — async/await, Sendable structs, URLSession, no third-party dependency)
- Python client (stable — pydantic v2 models, asyncio client, httpx and websockets adapters)
- Go client (stable — plain structs, context-aware methods returning (value, error), net/http and coder/websocket adapters)
- Express / Apollo server (stable — TypeScript, DataLoader batch mappings, graphql-ws subscriptions)

## Installation

Download the prebuilt binary from GitHub Releases:
https://github.com/Oualitsen/graphlink/releases/latest

Platforms: Linux (x86_64), macOS (ARM64), Windows (x86_64)

## Basic usage

```bash
glink                       # auto-discover glink.json / glink.yaml / glink.yml
glink -c glink.json         # explicit config path
glink -w                    # watch mode
glink -w --debounce 1000    # watch mode, wait 1000 ms after the last change (default 500)
glink -v                    # print version
glink -h                    # show help
```

## Configuration (glink.json / glink.yaml)

```json
{
  "schemaPaths": ["schema/*.gql"],
  "mode": "client",
  "typeMappings": { "ID": "String", "Float": "Double", "Int": "Integer", "Boolean": "Boolean" },
  "unknownScalarType": "Object",
  "outputDir": "src/main/java/com/example/generated",
  "clientConfig": {
    "java": {
      "packageName": "com.example.generated"
    }
  }
}
```

## Caching directives

```graphql
type Query {
  getCar(id: ID!): Car! @glCache(ttl: "5m", tags: ["cars"])
}
type Mutation {
  createCar(input: CreateCarInput!): Car! @glCacheInvalidate(tags: ["cars"])
}
```
